# 教材扩充知识点弹窗 UI 设计建议

> **范围：** 仅针对 `教材管理 > 教材详情 > 扩充知识点` 弹窗（`ExpandKnowledgePointsModal`）。本设计建议暂不涉及后端接口与数据模型变更。

---

## 1. 现状与问题

当前弹窗采用纵向单栏堆叠：说明文字 → 校验规则面板 → 校验结果 → 框架文件上传/预览 → 内容文件上传/预览 → 操作按钮。主要体验问题：

1. **纵向空间拥挤**：规则面板、预览表格、预览文本区全部堆叠，Modal 高度容易超出视口。
2. **xlsx / md 对照困难**：两个预览区不在同一视口内，教师核对内容时需要上下滚动。
3. **错误与预览脱节**：校验错误以文字列表形式展示在文件上传区之前，错误所在行/编号在预览中没有视觉高亮，用户需要手动对照。
4. **规则面板默认展开**：即使使用 ghost Collapse，仍占用较多首屏空间。
5. **md 预览可读性弱**：使用只读 `<Input.TextArea>` 展示原始 Markdown，标题层级、公式等无法快速识别。

---

## 2. 设计目标

- 在弹窗内同时呈现 xlsx 与 md 预览，便于教师对照。
- 将校验错误直接关联到预览中的具体行/编号，实现「看到错误即看到位置」。
- 降低首屏信息密度，把规则面板等非高频内容收纳起来。
- 保持现有操作流（选文件 → 预览 → 校验 → 提交），不引入新的后端概念。

---

## 3. 推荐方案：联动编辑器布局

### 3.1 整体布局

Modal 内容分为四层：

```
┌─────────────────────────────────────────────────────┐
│ 标题：扩充知识点    [查看校验规则]                    │
├──────────────────────┬────────────────────────────┤
│ 框架文件 (.xlsx)       │ 内容文件 (.md)              │
│ [选择文件]             │ [选择文件]                  │
│ +------------------+   │ +----------------------+  │
│ | xlsx 预览表格    |   │ | md 预览（带行号）    |  │
│ | 1.1.1 ✓          |   │ | 1 #### 1.1.1 ...     |  │
│ | 1.1.2 ✗ 已存在   |   │ | 2 ...                |  │
│ | 1.1.3 ✓          |   │ | 3 ✗ 层级错误         |  │
│ +------------------+   │ +----------------------+  │
├──────────────────────┴────────────────────────────┤
│ 校验结果                                            │
│ [✗ 编号 1.1.2：已存在] [✗ 第 3 行：标题层级错误]      │
│ 点击错误项自动滚动到对应预览位置                     │
├─────────────────────────────────────────────────────┤
│ 取消    开始校验    确认上传（校验通过后才可用）      │
└─────────────────────────────────────────────────────┘
```

- 采用 **左右双栏** 布局：左栏为 xlsx 上传与预览，右栏为 md 上传与预览。
- 校验规则面板不默认展开，改为顶部「查看校验规则」按钮触发 `Drawer` 或 `Popover`。
- 校验结果区域置于两栏下方，以「错误标签」形式展示，可点击联动。

### 3.2 组件变更建议

| 文件 | 建议变更 |
|------|----------|
| `ExpandKnowledgePointsModal.tsx` | 改用 Flex / Grid 双栏布局；新增 `xlsxErrors` / `mdErrors` 状态映射；集成 `ErrorTag` 与 `MdPreview` 组件。 |
| `ValidationRulesPanel.tsx` | 保持现有内容，但由 Modal 内直接渲染改为由按钮触发的 `Drawer` 渲染。 |
| 新增 `MdPreview.tsx` | 接收 `content: string` 和 `highlights: { line: number; message: string }[]`，渲染带行号的只读文本（或轻量 Markdown 渲染）。 |
| 新增 `ErrorTag.tsx` | 接收 `type`, `location`, `message`，点击时触发 `onClick(location)`。 |

### 3.3 预览区错误高亮规则

- **xlsx 预览**：
  - 在表格右侧增加一列「状态」，正常行显示 `✓`，错误行显示 `✗ 原因`。
  - 错误行整行背景使用 `var(--ant-color-error-bg)`（浅红）。
  - 鼠标悬停在错误行时，底部错误标签也高亮。

- **md 预览**：
  - 使用等宽字体 + 行号显示原始 Markdown。
  - 错误行背景浅红，并在错误行下方插入一行红色小字 `✗ 原因`。
  - 如果错误包含 `code`（编号），可通过正则高亮包含该编号的行。

### 3.4 错误-预览联动

1. 后端返回的 `ValidationIssue` 已包含 `location.code` 或 `location.row`。
2. Modal 维护两张映射表：
   - `xlsxErrorIndex: Record<string, ValidationIssue[]>` —— key 为 `code` 或行号。
   - `mdErrorIndex: Record<string, ValidationIssue[]>` —— key 为 `code` 或行号。
3. 点击错误标签时：
   - 在对应预览区查找目标行/编号。
   - 使用 `scrollIntoView` 滚动到该元素。
   - 临时添加 `pulse` 或 `ring` 动画以吸引注意。

### 3.5 md 预览渲染方式选择

有两种可行实现，建议按当前代码基础选择：

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A. 纯文本 + 行号 | 用 `<pre>` + 行号展示原始 md | 实现简单，与行号联动精确 | 无 Markdown 渲染效果 |
| B. 轻量 Markdown 渲染 | 使用现有 `MarkdownMessageContent` 组件 | 标题、公式更直观 | 行号映射复杂，需计算每个 heading 所在行 |

**建议**：先采用方案 A（纯文本 + 行号），因为错误定位以行号为主，精确滚动比渲染效果更重要。未来若需要更好的阅读体验，可再替换为方案 B。

### 3.6 规则面板收纳

- 将「校验规则」按钮放在 Modal 标题右侧或说明文字右侧。
- 点击后从右侧滑出 `Drawer`（宽度约 480px），里面渲染现有的 `ValidationRulesPanel`。
- 教师首次使用时可打开查看，熟练后不再占用首屏。

### 3.7 操作按钮状态

- **取消**：始终可用，点击清空文件和校验状态。
- **开始校验**：两个文件都已选择时可用；点击后禁用按钮并显示 `loading`。
- **确认上传**：仅在校验结果 `valid === true` 时启用，否则置灰。

---

## 4. 其他可选优化

1. **文件选择后自动预览**：当前已实现 xlsx 和 md 的客户端预览，可保留。
2. **文件变化时重置校验结果**：当前已实现，可保留。
3. **xlsx 预览行数限制**：当前限制 100 行，可保留；未来若文件过大，可提示「仅展示前 100 行」。
4. **空状态提示**：未选择文件时，预览区显示占位文字「选择文件后在此处预览」。

---

## 5. 实施风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 双栏布局在小屏幕上可能过窄 | 中 | 设置 Modal 最小宽度 960px；在窄屏下回退为单栏堆叠（使用 CSS media query）。 |
| 行号与滚动联动需要精确计算 | 中 | 方案 A（纯文本 + 行号）中每个行一个 `<div>`，可直接使用 `element.scrollIntoView()`。 |
| 错误标签过多时底部区域过高 | 低 | 错误标签可折叠，超过 3 个显示「+N 更多」展开按钮。 |

---

## 6. 验证建议（若后续实施）

1. 在 1920×1080 与 1366×768 两种分辨率下检查双栏布局是否挤压。
2. 上传一个包含多种错误（重复编号、层级错误、行号错误）的测试文件，检查高亮与联动是否准确。
3. 确保键盘 Tab 顺序合理：文件上传 → 校验按钮 → 错误标签 → 提交按钮。
4. 确认屏幕阅读器能正确朗读错误标签和状态列内容。

---

## 7. 结论

推荐采用 **联动编辑器布局（方案 C）**：左右双栏展示 xlsx / md 预览，行内高亮错误，错误标签与预览联动，规则面板以抽屉形式收纳。该方案在不改变后端的前提下，最大程度提升教师的校验效率和错误定位速度。
