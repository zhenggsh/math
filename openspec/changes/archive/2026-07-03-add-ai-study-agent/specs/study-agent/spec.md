## ADDED Requirements

### Requirement: Backend proxies Kimi API for student questions
The system SHALL provide a backend endpoint that receives student questions and returns answers generated by the KimiCode2.6 LLM.

#### Scenario: Student asks a question
- **WHEN** a student sends a question to `POST /api/study-agent/sessions/:sessionId/messages`
- **THEN** the system calls the Kimi API with the assembled prompt
- **AND** returns the LLM answer in the `agentMessage.content` field

### Requirement: Prompt includes knowledge point context
The system SHALL inject the current knowledge point title, hierarchy, and content summary into the LLM prompt.

#### Scenario: Question about current knowledge point
- **WHEN** a student asks a question while viewing "三角函数的基本概念"
- **THEN** the prompt includes the title, path, and a summary of the knowledge point content
- **AND** the LLM answer references that context

### Requirement: Knowledge point content summary is read from textbook Markdown files
The system SHALL read the current knowledge point content from the Markdown file referenced by `KnowledgePoint.contentRef`, falling back to `Textbook.contentPath`, and include a ~2000-character summary in the prompt.

#### Scenario: Content file exists
- **WHEN** the student is viewing "三角函数的基本概念"
- **THEN** the system reads the Markdown file referenced by `KnowledgePoint.contentRef`
- **AND** falls back to the file referenced by `Textbook.contentPath` if `contentRef` is not set
- **AND** locates the section by matching the knowledge point `code` or `title`
- **AND** injects a summary of up to ~2000 characters into the prompt

#### Scenario: Content file or section is missing
- **WHEN** the Markdown file does not exist or the section cannot be located
- **THEN** the system falls back to the first 2000 characters of the file
- **AND** if the file is also unavailable, the prompt uses only the title and hierarchy

### Requirement: Prompt includes recent learning records
The system SHALL include the student's most recent learning records for the current knowledge point in the prompt.

#### Scenario: Student has learning history
- **WHEN** the student has prior `LearningRecord` entries for the current knowledge point
- **THEN** the prompt includes the most recent 3 records with `masteryLevel` and `durationMinutes`
- **AND** the Agent adjusts its explanation depth accordingly

### Requirement: Prompt includes conversation history
The system SHALL include the most recent messages from the current Session in the LLM prompt.

#### Scenario: Multi-turn conversation
- **WHEN** a student has already exchanged 2 messages in the current Session
- **THEN** the prompt includes those 2 messages in chronological order
- **AND** the LLM answer continues the conversation coherently

### Requirement: Follow-up chips are parsed from LLM output
The system SHALL parse exactly 3 follow-up question chips from the LLM response.

#### Scenario: LLM returns valid JSON block
- **WHEN** the LLM answer ends with a valid JSON code block containing `followUps: ["q1", "q2", "q3"]`
- **THEN** the system returns those 3 strings in `agentMessage.followUps`

#### Scenario: LLM returns malformed follow-up block
- **WHEN** the LLM answer does not contain a valid follow-up JSON block
- **THEN** the system uses default fallback follow-ups based on the knowledge point
- **AND** returns them in `agentMessage.followUps`

### Requirement: Error handling for LLM failures
The system SHALL return a friendly error message when the Kimi API is unavailable, times out, or returns an error.

#### Scenario: API timeout
- **WHEN** the Kimi API call exceeds 30 seconds
- **THEN** the system returns HTTP 503 with the message "AI 助手暂时不可用，请稍后重试"

#### Scenario: Rate limit exceeded
- **WHEN** a user exceeds 20 requests per minute or 100 requests per hour
- **THEN** the system returns HTTP 429 with the message "请求太频繁，请稍后再试"

### Requirement: Agent configuration is loaded from files
The system SHALL load three Markdown files at startup and include them in the system prompt.

#### Scenario: Service starts
- **WHEN** the backend service starts
- **THEN** it reads `server/study-agent-config/Identity.md`, `Memory.md`, and `SOULE.md`
- **AND** caches their contents for prompt assembly

### Requirement: Agent message feedback is persisted
The system SHALL persist thumbs up/down feedback on agent messages.

#### Scenario: Student rates an answer
- **WHEN** a student clicks thumbs up or thumbs down on an agent message
- **THEN** the system stores the feedback value on the corresponding `StudyMessage` record
- **AND** the response confirms the update
- **AND** only the owning user can submit feedback for messages in their session

### Requirement: System protects against prompt injection
The system SHALL place user messages in the `user` role after the system prompt messages so that user input cannot override the system instructions.

#### Scenario: Malicious user input attempts to override instructions
- **WHEN** a user sends a message containing instructions intended to override the system prompt
- **THEN** the system keeps the user input within the `user` message role
- **AND** the Agent responds based on the intended question without altering its identity or constraints

### Requirement: System supports regenerating an agent response
The system SHALL support regenerating an answer for the last user message in a session by calling the LLM again with the conversation context from before the original agent response.

#### Scenario: Student regenerates the latest answer
- **WHEN** a student triggers regenerate on the latest agent message by sending `POST /messages/:userMessageId/regenerate`
- **THEN** the system identifies the last agent message that followed the specified user message
- **AND** re-calls the LLM with the same conversation context used for the original answer
- **AND** updates the existing agent message with the new content and follow-ups
- **AND** the regenerate request counts toward the user's rate limit
