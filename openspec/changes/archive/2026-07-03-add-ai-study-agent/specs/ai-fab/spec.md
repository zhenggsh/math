## MODIFIED Requirements

### Requirement: FAB is always visible on LearningPage when a knowledge point is selected
The system SHALL keep the FAB visible on LearningPage when a knowledge point is selected.
Position: fixed to bottom-right corner (24px from edges).
Size: 56px diameter circle button.

#### Scenario: Student views a knowledge point
- **WHEN** a student is on LearningPage with a selected knowledge point
- **THEN** a FAB is visible at bottom-right
- **AND** the FAB uses a robot icon

### Requirement: Panel expansion
The system SHALL expand a panel when the FAB is clicked.
Panel width: 380px desktop, full-width mobile.
Panel max-height: 70vh.
Panel has close button and closes on outside click or ESC key.

#### Scenario: Student clicks FAB
- **WHEN** a student clicks the FAB
- **THEN** a chat panel expands from the right side
- **AND** the panel displays the current knowledge point context
- **AND** the panel shows historical messages if a session exists
- **AND** the panel closes on outside click or ESC key

### Requirement: Prompt suggestions are replaced by free-form chat
The system SHALL allow students to type any question instead of selecting from 3 fixed prompt chips.

#### Scenario: Student types a custom question
- **WHEN** a student types "sin 和 cos 怎么区分？" and sends it
- **THEN** the system sends the question to the backend
- **AND** displays the agent response

### Requirement: Responses are generated by the LLM
The system SHALL display real LLM-generated responses instead of mock text.

#### Scenario: Agent answers a question
- **WHEN** a student asks a question
- **THEN** the backend calls the Kimi API
- **AND** the chat displays the real LLM response
- **AND** the response includes 3 follow-up chips

### Requirement: State is preserved across panel close
The system SHALL preserve the current conversation state when the panel is closed and reopened.

#### Scenario: Student closes and reopens panel
- **WHEN** a student closes the panel
- **AND** reopens it for the same knowledge point
- **THEN** the previous messages are still visible

### Requirement: Knowledge point switch behavior
The system SHALL load the session for the new knowledge point when `knowledgePointId` changes while the panel is open.

#### Scenario: Student switches knowledge point
- **WHEN** a student switches from "三角函数的基本概念" to "同角三角函数关系"
- **THEN** the panel loads the session for the new knowledge point
- **AND** any in-progress request is discarded

## REMOVED Requirements

### Requirement: Mock Response Display
**Reason**: Replaced by real LLM integration via the `study-agent` capability.
**Migration**: The `ai-study-panel` capability now calls the backend API and displays real responses.

### Requirement: Prompt Suggestions
**Reason**: Replaced by free-form chat input and automatic follow-up chips after each agent response.
**Migration**: Students type questions directly; the backend returns 3 follow-up chips automatically.

## Non-Functional Changes

- The panel animation transitions remain 200ms CSS ease-out.
- The panel is responsive on desktop and mobile.
- The FAB and panel z-index must remain above the allotment sash (z-index > 100).
