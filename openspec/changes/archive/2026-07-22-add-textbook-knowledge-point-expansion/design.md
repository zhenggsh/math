# Design: 教材详情页与知识点扩充

## Context

教材管理模块已支持教材列表、上传、删除和刷新同步。教师现在需要查看单本教材的知识点详情，并能在教材建立后追加新的知识点，而无需重新上传整套教材文件。该功能涉及文件追加、并发控制和前后端新增界面。

## Goals / Non-Goals

**Goals:**
- 提供教材详情页，展示教材元数据和知识点列表。
- 支持教师上传新的 xlsx + md 文件向现有教材追加知识点。
- 追加前校验编号冲突，避免覆盖或重复。
- 在并发环境下保证同一教材的扩充操作串行执行。
- 新知识点同时写入数据库并追加到原 xlsx 与 md 文件。
- 为新增功能提供前后端测试覆盖。

**Non-Goals:**
- 不修改教材上传流程的核心逻辑。
- 不支持 CSV 教材的扩充（当前仅支持 xlsx）。
- 不自动为无内容文件的教材生成 md 文件；若原教材无 md，扩充仍需上传 md。
- 不实现知识点编辑、删除或重排。

## Decisions

### D1: 使用教材详情页承载扩充入口
- **Decision**: 在教材管理列表增加「详情」按钮，点击后进入 `/teacher/textbooks/:id` 详情页，详情页内展示知识点列表并提供「扩充知识点」按钮。
- **Rationale**: 详情页是查看和编辑单本教材的自然场所，扩充操作与知识点列表相邻，教师可立即看到追加结果。
- **Alternative**: 在列表页直接弹出扩充上传框。缺点：教师无法先查看现有知识点结构，容易误操作。

### D2: 新知识点追加到原文件而非重建文件
- **Decision**: `expandKnowledgePoints` 调用 `appendXlsxRows` 和 `appendMdContent` 在原 `frameworkPath` 与 `contentPath` 文件末尾追加新数据。
- **Rationale**: 保留原文件内容，避免全量重写带来的风险；与数据库增量写入语义一致。
- **Alternative**: 重新生成完整文件。缺点：实现更复杂，且会丢失原文件中可能存在的非结构化内容。

### D3: 使用 PostgreSQL advisory lock 处理并发
- **Decision**: 在事务内通过 `pg_advisory_xact_lock(<textbookId-hash>)` 锁定教材，再二次检查现有知识点编号。
- **Rationale**: 事务锁与数据库操作绑定，无需额外分布式锁组件；跨实例部署时仍有效。
- **Alternative**: 使用应用内存锁。缺点：多实例部署下无法保证互斥；使用文件锁或 Redis 增加额外依赖。

### D4: 先解析校验、后加锁冲突检测
- **Decision**: 解析上传的 xlsx 并完成内部校验后，先检查 md 中 code 是否为 xlsx 子集；进入事务加锁后再查询数据库做最终冲突检测。
- **Rationale**: 轻量校验在加锁前完成，减少持有数据库锁的时间；最终冲突检测在锁保护下进行，避免竞态条件。
- **Alternative**: 所有校验在加锁后完成。缺点：会延长锁持有时间，降低并发度。

### D5: 临时文件保存上传内容
- **Decision**: 上传的 xlsx/md 文件先保存到 `os.tmpdir()` 的临时文件，解析完成后在 `finally` 中删除。
- **Rationale**: 复用现有的 `parseFrameworkFile`（基于文件路径）；避免污染 `iksm/` 目录；临时文件以 `.tmp-` 开头，不会被文件扫描逻辑误处理。
- **Alternative**: 修改解析器支持 Buffer。缺点：改动范围扩大，且需要额外测试。

### D6: md 内容块按 code 层级插入
- **Decision**: md 追加按 code 层级寻找父级 block，将新内容插入父级 block 末尾；找不到父级时追加到文件末尾。
- **Rationale**: 保持教材层级结构清晰，新三级知识点紧跟同级兄弟节点之后。
- **Alternative**: 统一追加到文件末尾。缺点：会破坏层级就近关系。

## Risks / Trade-offs

- **[Risk] 追加写入失败可能导致 xlsx 与 md 不一致。** → **Mitigation**: 所有文件操作与数据库写入在同一事务中完成，但文件系统无法回滚。错误处理会抛出异常，后续手动恢复或重新上传即可。
- **[Risk] 并发冲突检测窗口期。** → **Mitigation**: 使用事务级 advisory lock，保证同一教材扩充串行化；冲突检测在加锁后再次执行。
- **[Risk] 原 xlsx 格式与追加格式不完全一致。** → **Mitigation**: 追加时复用原工作表结构，仅扩展 `!ref` 范围并写入单元格数据；目前为 best-effort，已满足项目需求。
- **[Risk] md 父级 block 匹配依赖现有标题格式。** → **Mitigation**: 严格匹配 `## code name`、`### code name`、`#### 知识点 code：name` 格式，与现有教材规范一致。

## Migration Plan

无需数据库迁移。新路由和接口向后兼容，现有教材列表页功能不变。部署后教师即可使用「详情」入口。
