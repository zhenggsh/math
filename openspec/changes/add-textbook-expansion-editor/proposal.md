## Why

Teachers currently have to switch back to local Excel and Markdown editors whenever the "expand knowledge points" upload fails validation. This round-trip is the main bottleneck in refining a textbook's knowledge outline. Adding an in-browser editor inside the same modal lets teachers fix xlsx rows and Markdown content blocks immediately after seeing the validation report, then re-validate and confirm without leaving the browser.

## What Changes

- Add an **edit mode** to the second step of the existing "Expand Knowledge Points" modal (`ExpandKnowledgePointsModal`).
- Provide a row-editable xlsx table (`FrameworkEditor`) with add/delete/insert operations and row-level validation.
- Provide a Markdown editor (`MdEditor`) with line numbers, direct text editing, and batch heading-level replacement (`##` ↔ `###` ↔ `####`).
- Keep xlsx → Markdown synchronization one-way: changing a row updates the corresponding Markdown block's heading and structure; editing Markdown body text does not flow back to xlsx.
- After any edit, the validation result is cleared and the teacher must click **Re-validate** before proceeding to the confirmation step.
- Persist edited rows and Markdown content in `sessionStorage` so the draft survives accidental modal closure, as long as the original uploaded files do not change.
- Add serialization utilities to turn the edited in-memory state back into `File` objects that the existing `POST /textbooks/:id/validate` and `POST /textbooks/:id/expand` endpoints can consume.
- **CSV files remain read-only** in this iteration; the "Enter edit mode" button is disabled with a tooltip when the uploaded framework is a CSV.
- **Multi-sheet xlsx files** are warned before editing: non-first sheets will be lost because the editor only reads and writes the first sheet.
- **Large Markdown files** (>1 MB) disable textarea editing and prompt the teacher to edit locally.
- Add unit and integration tests for serialization round-trip, `KnowledgeBlock` parsing/sync, and the edit-mode flow.

## Capabilities

### New Capabilities
- `textbook-expansion-editor`: In-browser editing of xlsx framework rows and Markdown content blocks for the "expand knowledge points" feature, including xlsx ↔ md synchronization, batch heading replacement, draft persistence, and re-validation.

### Modified Capabilities
- `textbook-knowledge-point-expansion`: The preview/validation step of the expansion modal now supports entering edit mode, editing rows and Markdown, clearing validation results on edits, and re-validating from the edited files.

## Impact

- **Frontend**: `ExpandKnowledgePointsModal`, new `FrameworkEditor` / `MdEditor` components, new `useExpansionEditor` hook, `textbookFilePreview.ts` serialization utilities, `sessionStorage` draft shape, and new tests.
- **Backend**: No new endpoints. Existing `POST /textbooks/:id/validate` and `POST /textbooks/:id/expand` remain unchanged. The backend must continue to parse the xlsx generated by the frontend's serializer (verified by a prerequisite round-trip test).
- **Dependencies**: Uses the browser-side `xlsx` library already present in the web package.
- **User experience**: Teachers can fix validation errors in the browser, reducing the local-file round-trip loop.
